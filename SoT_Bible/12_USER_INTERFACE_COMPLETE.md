## Навигационная карта (User Sitemap)

```
/onboarding          ← первый запуск
  /onboarding/role
  /onboarding/hub
  /onboarding/lang

/feed                ← главная лента (Tab 1)
/request/:id         ← карточка заказа + аукцион
/create              ← создание заказа (Tab 2, FAB)
  /create/category
  /create/details
  /create/preview

/chats               ← активные сделки (Tab 3)
/chats/:deal_id      ← внутренний чат по сделке

/profile             ← профиль (Tab 4)
  /profile/orders    ← мои заказы
  /profile/reviews   ← мои отзывы
  /profile/settings  ← настройки

/notifications       ← лог уведомлений
/search              ← поиск бизнесов
/review/:bid_id      ← написание отзыва
/provider/:id        ← публичная карточка исполнителя
/payment             ← покупка токенов
/saved               ← Избранные исполнители (сердечка)
```

## 📍 Система геолокации — Полная спецификация

### Логика по категориям

> **6 типов локации:** `gps` · `map_pin` · `address` · `district` · `virtual` · `meetup` · `pickup_fixed`

| Категория | Тип | `location_type` | Авто-GPS | Примечание |
|---|---|---|---|---|
| 🧹 Клининг | Выездная | `gps` | ✅ авто | Точка дома/виллы |
| 💆 Массаж на дому | Выездная | `gps` | ✅ авто | Точка отеля |
| 🚗 Доставка байка | Выездная | `gps` | ✅ авто | Точка отеля |
| 🚕 Трансфер | Выездная A→B | `gps` + `address` | ✅ авто (A) | Две точки |
| 🔧 Ремонт | Выездная | `gps` | ✅ авто | Точка дома |
| 👶 Сиделка | Выездная | `gps` | ✅ авто | Точка дома |
| 💆 Спа-центр | Стационарная | `district` | ❌ | Место провайдера |
| 🍽️ Ресторан | Стационарная | `district` | ❌ | Место провайдера |
| 🗺️ Туры | Смешанная | `map_pin` (опц.) | ⚠️ опц. | Точка сбора |
| 🏡 Жильё | Смешанная | `map_pin` (опц.) | ⚠️ опц. | Адрес объекта |
| 🛂 **Визаран** | Выезд A→B(fix) | `pickup_fixed` | ✅ авто (A) | B = граница (из списка) |
| 💱 **Обмен (P2P/онлайн)** | **Виртуальная** | `virtual` | ❌ | Перевод без встречи |
| 💵 **Обмен (наличные)** | **Встреча** | `meetup` | ❌ | Клиент выбирает точку |

### Telegram WebApp API: запрос геолокации

```typescript
// frontend/src/hooks/useGeoLocation.ts

export async function requestTelegramLocation(): Promise<{
  lat: number; lng: number; accuracy: number;
} | null> {
  return new Promise((resolve) => {
    // Telegram Mini App v6.9+
    if (window.Telegram?.WebApp?.LocationManager) {
      window.Telegram.WebApp.LocationManager.getLocation((location) => {
        if (!location) { resolve(null); return; }
        resolve({
          lat: location.latitude,
          lng: location.longitude,
          accuracy: location.horizontal_accuracy ?? 50,
        });
      });
    } else {
      // Fallback: browser Geolocation API
      navigator.geolocation.getCurrentPosition(
        (pos) => resolve({
          lat: pos.coords.latitude,
          lng: pos.coords.longitude,
          accuracy: pos.coords.accuracy,
        }),
        () => resolve(null),
        { timeout: 5000, enableHighAccuracy: true }
      );
    }
  });
}

// Обратное геокодирование lat/lng → район
export async function reverseGeocode(lat: number, lng: number): Promise<{
  district: string; address: string;
}> {
  // Используем Nominatim (OpenStreetMap) — бесплатно
  const resp = await fetch(
    `https://nominatim.openstreetmap.org/reverse?lat=${lat}&lon=${lng}&format=json`
  );
  const data = await resp.json();
  return {
    district: data.address?.suburb ?? data.address?.quarter ?? data.address?.city_district ?? 'Unknown',
    address: data.display_name,
  };
}
```

## Screen 15: Избранное — Бизнесы и Услуги (`/saved`)

> **Два режима сохранения.** ❤️ Сохранить **бизнес** (карточку компании) или 🔄 Сохранить **услугу** (конкретный оффер для повторного заказа). Прямой чат без заявки — **недоступен в обоих случаях.** Чат открывается только после принятия оффера.

---

### Почему нет прямого чата

| Сценарий | Проблема |
|---|---|
| Клиент пишет провайдеру напрямую → договариваются вне платформы | Платформа теряет доход (0 токенов) |
| История не фиксируется | Нет защиты клиента, нет отзыва |
| Провайдер принимает наличные | Bypass всей системы |

**Решение:** сохранённый бизнес/услуга всегда ведёт к **Прямой заявке** — она выглядит как прямое обращение, но проходит через механику платформы.

**Прямой чат без заявки — невозможен в обоих случаях.**  
Провайдер платит токены при принятии оффера — механика не нарушается.

## DB: Расширенная таблица saved_providers

```sql
CREATE TYPE saved_type AS ENUM ('business', 'service');

CREATE TABLE saved_providers (
    id              UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    user_id         UUID REFERENCES profiles(id) ON DELETE CASCADE NOT NULL,
    provider_id     UUID REFERENCES profiles(id) ON DELETE CASCADE NOT NULL,

    -- Тип сохранения
    save_type       saved_type NOT NULL DEFAULT 'business',

    -- Данные для режима 'service' (снимок оффера)
    service_name    VARCHAR(128),        -- «Масляный массаж 90 мин»
    service_price   NUMERIC(10,2),       -- 35.00
    service_currency VARCHAR(8) DEFAULT 'USD',
    category_l1     VARCHAR(64),         -- 🧹 cleaning
    bid_snapshot    JSONB DEFAULT NULL,  -- {price, currency, comment, bid_id}

    -- Пользовательская заметка
    note            TEXT,

    -- Откуда сохранено
    source          VARCHAR(32) DEFAULT 'bid', -- 'bid' | 'profile' | 'search' | 'post_deal'

    -- Напоминание (только для save_type = 'service')
    reminder_enabled    BOOLEAN DEFAULT FALSE,
    reminder_frequency  VARCHAR(16),     -- 'weekly' | 'biweekly' | 'monthly'
    reminder_day_of_week SMALLINT,       -- 0=Sun, 1=Mon ... 6=Sat
    reminder_time       TIME,            -- 18:00:00
    reminder_next_at    TIMESTAMP WITH TIME ZONE,
    reminder_last_sent  TIMESTAMP WITH TIME ZONE,

    created_at      TIMESTAMP WITH TIME ZONE DEFAULT NOW(),

    UNIQUE(user_id, provider_id, save_type)  -- бизнес + услугу можно оба
);

CREATE INDEX idx_saved_user      ON saved_providers(user_id, save_type, created_at DESC);
CREATE INDEX idx_saved_reminder  ON saved_providers(reminder_next_at)
    WHERE reminder_enabled = TRUE;

-- RLS
ALTER TABLE saved_providers ENABLE ROW LEVEL SECURITY;
CREATE POLICY "saved_own"
    ON saved_providers FOR ALL
    USING (auth.uid() = user_id)
    WITH CHECK (auth.uid() = user_id);

-- ============================================================
-- Direct Request: расширение таблицы requests
-- ============================================================
ALTER TABLE requests
    ADD COLUMN IF NOT EXISTS is_direct          BOOLEAN DEFAULT FALSE,
    ADD COLUMN IF NOT EXISTS direct_provider_id UUID REFERENCES profiles(id);
```

## CRON: Рассылка напоминаний об услугах

```sql
-- Каждые 15 минут проверяем reminder_next_at
SELECT cron.schedule(
    'service-reminders',
    '*/15 * * * *',
    $$
        SELECT id, user_id, provider_id, service_name,
               reminder_frequency, reminder_day_of_week, reminder_time
        FROM saved_providers
        WHERE reminder_enabled = TRUE
          AND reminder_next_at <= NOW()
          AND save_type = 'service'
        -- → для каждой записи:
        --   1. Отправить Push через GrammyJS
        --   2. Обновить reminder_next_at = NOW() + interval по частоте
        --   3. reminder_last_sent = NOW()
    $$
);
```
