# 📁 04_USER_JOURNEYS_AND_FLOWS.md
> **NeedTnow** — Пользовательские сценарии и флоу (User Journeys)

---

## Flow 1: Публикация заказа (Клиент)

```
[Экран 1: Главная / Лента] ──► Кнопка "+ Создать заказ" (FAB)
       │
       ▼
[Экран 2: Выбор мегакатегории L1]
       ├─► 🚗 Транспорт
       ├─► 🏡 Жильё
       ├─► 🧹 Клининг
       ├─► 🍽️ Еда
       ├─► 💆 Красота
       ├─► 🗺️ Туры
       └─► 🔧 Прочие услуги
       │
       ▼
[Экран 3: Уточнение категории L2 и L3]
       ├─► Горизонтальный скролл chips для L2
       └─► Вертикальный список L3 (с диапазоном цен как подсказка)
       │
       ▼
[Экран 4: Форма заказа]
       ├─► Заголовок (авто-заполняется из L3 slug + редактируется)
       ├─► Описание (Текст + кнопка 🎤 голосовой ввод)
       ├─► Фото (до 3 файлов — Supabase Storage)
       ├─► Район (Drop-down по хабу / 📍 Геолокация)
       └─► Бюджет (Поле ввода $ или переключатель «💬 Жду предложений»)
       │
       ▼
[Нажатие «Опубликовать»]
       ├─► INSERT в таблицу `requests` (status = 'open')
       ├─► Supabase Webhook → FastAPI AI Worker (trigger auto-bidding)
       └─► PUSH через Telegram Bot всем исполнителям в данном районе
```

## Flow 2: Отклик Исполнителя

### Вариант А: Manual (Человек)

```
[Push-уведомление в Telegram]
«📣 Новый заказ в Раваи: Honda PCX на 7 дней — $80»
       │
       ▼ (Deep Link → TMA /request/:id)
[Экран: Карточка заказа]
       ├─► Читает описание, фото, бюджет клиента
       └─► Нажимает «Сделать предложение»
              │
              ▼
       [Боттом-шит (Modal)]
       ├─► Вводит цену ($11/день)
       ├─► Добавляет комментарий
       └─► Нажимает «Отправить предложение»
              │
              ▼
       INSERT в `bids` (bid_type = 'manual')
       └─► Realtime Push → Клиент видит новый оффер мгновенно
```

### Вариант Б: AI Agent (Автономный, 3–5 секунд)

```
[INSERT в `requests`]
       │
       ▼
[Supabase DB Webhook → POST /api/v1/ai/trigger-auction]
       │
       ▼
[FastAPI AI Worker]
       ├─► Находит всех business_profiles WHERE ai_enabled=TRUE
       │    AND category_id matches AND hub matches
       │
       ▼
[LLM Engine (GPT-4o-mini)]
       ├─► Сопоставляет заказ с knowledge_base бизнеса
       ├─► Проверяет ai_min_budget (guardrail)
       └─► Генерирует JSON: {can_bid, proposed_price, comment}
              │
              ▼
       [Если can_bid = true]
       INSERT в `bids` (bid_type = 'ai_agent')
       └─► Клиент получает push «🤖 AI-менеджер ответил за 4 сек»
```

## Flow 3: Принятие оффера (Клиент)

```
[Экран: Карточка заказа]
       ├─► Просматривает все офферы (отсортированы по цене / рейтингу)
       ├─► Нажимает «Принять предложение» у выбранного оффера
       │
       ▼
[Диалог подтверждения]
       └─► «Подтвердить сделку с [Имя исполнителя] за $X?»
              │
              ▼
       UPDATE bids SET status = 'accepted' (выбранный)
       UPDATE bids SET status = 'rejected' (остальные)
       UPDATE requests SET status = 'in_progress'
              │
              ▼
       [Telegram Bot создаёт общий чат или ссылку]
       └─► Push обоим: «✅ Сделка! Свяжитесь для уточнения деталей»
```

## Flow 4: Партнёрская программа (Привлечение пользователей)

```
[Партнёр открывает кабинет /partner]
       │
       ▼
[Получает уникальную реф-ссылку]
       «t.me/NeedTnow_bot?start=REF_CODE123»
       │
       ▼
[Публикует в соцсетях / чатах / личных сообщениях]
       │
       ▼
[Новый пользователь переходит по ссылке]
       ├─► В profiles.referred_by записывается partner_id
       └─► Пользователь проходит онбординг и регистрируется
              │
              ▼
[Новый пользователь оплачивает подписку PRO ($19) или AI ($49)]
       │
       ▼
[Supabase Function автоматически]
       INSERT в partner_earnings:
       ├─► commission_pct = 20%
       ├─► commission_amount = $3.80 (PRO) или $9.80 (AI)
       └─► Push партнёру: «💰 +$3.80 за нового PRO-пользователя!»
              │
              ▼
[Партнёр запрашивает выплату (мин. $20)]
       └─► Выплата на TON кошелёк / USDT / PromptPay
```

## Flow 6: Оплата услуг (Прямая оплата)

**Важно:** Платформа NeedTnow **не принимает** оплату за услуги как посредник (без escrow). Клиент платит напрямую исполнителю.

```
[Сделка подтверждена, status = 'in_progress']
       │
       ▼
[Клиент и Исполнитель в чате]
       ├─► Исполнитель присылает реквизиты или договаривается о наличных
       ├─► Клиент оплачивает напрямую (Наличные, Перевод, Крипта и т.д.)
       └─► Платформа выступает только гарантом связи и отзывов
```

## Flow 7: Редактирование заявки (До принятия оффера)

```
[Экран заявки: статус 'open']
       │
       ▼
[Клиент нажимает "Редактировать"]
       ├─► Открывается форма заказа (предзаполненная)
       ├─► Изменяет описание, фото или бюджет
       └─► Нажимает "Сохранить"
              │
              ▼
[Система обновляет `requests`]
       ├─► UPDATE requests
       └─► PUSH-уведомление всем биддерам (кто уже оставил оффер):
           «Заявка обновилась, вот новый вариант»
              │
              ▼
[Исполнитель пересматривает заявку]
       └─► Может отозвать свой оффер или оставить его
```

## Flow 8: Отмена и срыв сделки (Cancellation & No-show)

### Вариант А: Отмена до принятия оффера
```
[Заявка 'open' / Оффер 'pending']
       ├─► Клиент может отменить заявку (status -> 'cancelled')
       └─► Исполнитель может отозвать оффер (delete bid)
```

### Вариант Б: Отмена после принятия оффера (До подтверждения исполнения)
```
[Сделка 'in_progress']
       │
       ▼
[Один из участников нажимает "Отменить сделку"]
       ├─► Отправляется запрос на подтверждение второму участнику
       │      │
       │      ├─► [Участник 2: ✅ Согласен] → Сделка отменяется мирно (status -> 'cancelled')
       │      │
       │      └─► [Участник 2: ❌ Отказ] → Автоматически открывается Апелляция
```

### Вариант В: Неявка исполнителя (No-show)
```
[Сделка 'in_progress', исполнитель не приехал]
       │
       ▼
[Клиент нажимает "⚖️ Апелляция (Неявка)"]
       ├─► Администратор рассматривает переписку и подтверждает неявку
       │
       ▼
[Действия платформы по факту неявки]
       ├─► Сделка переходит в 'cancelled' (по вине исполнителя)
       ├─► Штраф в рейтинг бизнеса, публикация автоматического негативного отзыва
       └─► Кнопка для клиента "🔄 Опубликовать заявку повторно"
              │
              ▼
       [Новая заявка 'open' (с сохранением старых данных)]
```

## Flow 9: Архив, Повтор заказа и Избранное

```
[Навигация: Вкладка "Архив / Избранное"]
       │
       ├─► [Таб: Архив заказов]
       │      ├─► Список завершенных/отмененных заявок
       │      ├─► Кнопка «Повторить заказ» (вызов того же исполнителя, если он доступен)
       │      └─► Кнопка «Повторить заявку» (создание новой открытой заявки с теми же параметрами -> открывает форму редактирования)
       │
       └─► [Таб: Избранное]
              ├─► Сохраненные бизнесы (Кнопка ❤️ на карточке бизнеса)
              └─► Быстрый переход в профиль бизнеса для прямой заявки
```
